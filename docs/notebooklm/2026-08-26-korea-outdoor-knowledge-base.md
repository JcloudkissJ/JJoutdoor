## 왜 만드는가

국내 산에서 외국인 등산객이 늘어나는 현장 관찰에서 출발했다. 대상은 두 집단이다.

| 집단 | 언어 | 필요 |
|---|---|---|
| 인바운드 관광객 | 영어, 중국어, 일본어 | 서울에서 반나절 안에 다녀올 곳 하나 |
| 국내 체류 외국인 | 몽골어, 싱할라어, 말레이어, 러시아어 | 거주지 근처, 반복 가능한 곳 |

값은 추천코스가 실제로 오르는 금오산 정상에 해당하는 468m 를 썼다. 남산은 봉우리가
여럿이라 두 기관이 다른 지점을 잰 것으로 보이나 **확인되지 않았다.**

> ⚠️ **10% 허용치는 표고에 너무 느슨하다.** 0.01% 와 5.79% 를 같은 `verified` 로 판정한다.
> `reconcile()` 을 실제로 배선할 때 지표별 허용치를 다시 정해야 한다.

## 2-7. 기각된 접근 — 순 상승 계산 (`315e722` → `b0d983f`)

**했던 것**: 산림청 등산로 폴리라인 꼭짓점을 WGS84 로 옮겨 SRTM30m DEM 으로 찍고,
최고점−최저점을 "순 상승"으로 삼아 Naismith 에 넣었다(아차산 266m, 인왕산 253m).

**왜 기각했나**: 계산값이 사람이 적어둔 값보다 **오히려 짧게** 나왔다(80→60분, 90→65분).
순 상승은 누적고도보다 작고 휴식·하산도 빠져 있어 **구조적으로 짧게 나온다.**
그 위험을 "표시된 시간은 최소치입니다" 문구로 덮는 것보다 **계산을 안 하는 편이 낫다.**

**다시 시도하기 전에**: 기술적으로는 작동했다. 막힌 것은 정확도가 아니라 **방향**이다.
되돌린 코드는 `315e722` 에 그대로 있다. 2-5 도 함께 보라 — 없다고 믿고 계산한 것이
실은 처음부터 손에 있었던 전례가 하나 더 있다.

## 2-8. 산림청 노선 데이터에 공식 시간이 있으나 코스 단위가 아니다

"계산 말고 공식 등산로를 채용"할 수 있는지 확인한 기록이다.

```
아차산 112150201  노선 246   PMNTN_UPPL(상행분) 246/246 채움
인왕산 114100401  노선  81   PMNTN_UPPL          81/81  채움 · PMNTN_NM 29/81
```

**상행분은 100% 채워져 있다.** 그런데 `PMNTN_NM` 이 코스명이 아니다 —
`중곡동구간`·`광장동구간` 같은 **행정동 묶음**이다(아차산 중곡동구간 = 98개 선분 12km 합계).
코스 시간으로 쓰려면 경로를 골라 합산해야 하고 그것도 계산이다. **그래서 채용하지 않았다.**

## 2-9. 아차산 `coords` 는 정상이 아니다 (미수정)


`astro.config.mjs` 의 `site` 가 **계획서에 예시로 적힌 가상 주소 그대로**였다. 실제 배포는
Cloudflare Workers 의 `morning-pine-5579.cartroad.workers.dev` 인데, 사이트가 검색엔진에
"정본은 다른 도메인에 있다"고 말하고 있었던 것이다. 그 도메인은 존재하지도 않는다.

**사람 눈에는 멀쩡했다.** 페이지는 200 으로 뜨고 한글도 정상이고 카드도 다 보인다.
깨진 것은 기계만 읽는 부분이라 화면을 봐서는 알 수 없었다 — 배포 후 `curl` 로 `hreflang` 과
`sitemap` 을 직접 읽어서 잡았다.

`site` 한 줄을 고치고 재빌드·재업로드한 뒤 캐시를 우회해 다시 받아 확인했다:

```
hreflang="ko" href="https://morning-pine-5579.cartroad.workers.dev/ko/half-day-from-seoul/"
옛 도메인 잔존: /ko/half-day-from-seoul/ 0건 · /en/ 0건 · /ko/mountain/gyeongju-namsan 0건
```

> ⚠️ **커스텀 도메인을 붙이면 같은 한 줄만 다시 바꾼다.** hreflang·sitemap·canonical 이
> 전부 거기서 파생되므로, 바꾸고 **반드시 재배포한 뒤 실제 URL 로 확인**한다.
> 로컬 빌드가 맞다고 배포본이 맞은 것은 아니다.

## 2-14. 모든 장소 카드가 404 였다 — 배포 후에야 사람이 눌러보고 발견

사용자가 사이트를 쓰다가 404 를 만났다. URL 이 이랬다:

```
https://morning-pine-5579.cartroad.workers.dev/mountain/inwangsan   ← /ko/ 가 없다
```

규칙 9 는 `/{lang}/{type}/{slug}` 인데 링크에 언어 접두어가 빠져 있었다.

**증상이 난 곳만 고치면 안 됐다.** `href` 를 만드는 곳을 전부 훑었더니 **세 곳이 같은
실수를 하고 있었다** — 목록·지역·반나절 페이지가 각자 링크를 만들고 각자 빼먹었다.

```
src/pages/[lang]/mountain/index.astro:44
src/pages/[lang]/near/[region].astro:45
src/pages/[lang]/half-day-from-seoul.astro:48
```

즉 **사이트의 모든 장소 카드가 404 였다.** URL 을 직접 치면 열리므로 눈에 띄지 않았다.

### 왜 못 잡았나 — 이것이 핵심이다

`75d8f80`(Task 10) 이후 줄곧 있었다. 그동안:

- 빌드는 통과했다 — 링크 문자열은 빌드가 검사하지 않는다
- e2e 는 목록 페이지를 열고, 카드 개수를 세고, WCAG 를 검사하고, 375px 오버플로까지 봤다
- Lighthouse 는 접근성·SEO 100 을 줬다
- 그런데 **어느 검사도 카드를 눌러본 적이 없다**

**200 이 뜨고 카드가 보이는 것은 사이트가 동작한다는 뜻이 아니다.**
사용자가 실제로 하는 행동(링크를 누른다)을 아무도 흉내내지 않았다.

### 넣은 가드

카드를 실제로 눌러보는 검사 6건 — en·ko × 목록·지역·반나절.
`href` 가 `/{lang}/mountain/` 로 시작하는지 확인하고, **실제로 이동해 200 과 h1 을 본다.**

임시로 버그를 되살려 가드가 발동하는지 확인했다 — 2건 실패하며
`Received "/mountain/baegunsan-pocheon"` 을 그대로 보여준다. 확인 후 되돌렸다.

# 3부 · 설계 원칙과 불변 규칙

## 유지되는 규칙 1~12

1. **언어 목록은 `src/config/languages.ts` 한 곳에만.**
2. **구조화 필드는 언어 독립.** `duration_min: 90` 이지 `"약 1시간 30분"` 이 아니다.
3. **`null` 은 "미확인"이며 절대 긍정 필터를 만족시키지 않는다.**
4. **조용한 실패보다 시끄러운 빌드 실패.**
5. **검증하지 않은 것을 검증했다고 표시하지 않는다.**
6. **번역 2등급.** 안전 정보는 사람 검수 의무.
7. **폰트는 언어별 스크립트만 로딩.**
8. **Swiss Modernism, 라이트 모드 고정.**
9. **URL 은 `/{lang}/{type}/{slug}`.**
10. **수치마다 출처를 데이터와 화면에 남긴다.**
11. **근거 없는 보정 계수를 넣지 않는다.**
12. **타인의 데이터를 출처로 삼지 않는다.**

## 규칙 13 — 소요시간은 계산하지 않는다

**공식 등산로가 공개한 값을 인용한다.** 없으면 사람이 적은 값(`manual`)으로 두고
화면에 "검증되지 않음"이 뜨게 둔다. **비어 보이는 것이 틀린 것보다 낫다.**

계산이 금지인 이유는 부정확해서가 아니라 **틀리는 방향이 위험해서**다(2-7).
소요시간을 짧게 제시하면 해가 진 뒤 하산하는 사람이 생긴다.

기관이 적어둔 총 소요시간을 **분으로 바꾸는 것은 계산이 아니다**(규칙 2가 요구하는 형식 변환).
그러나 **구간 시간을 합산하는 것은 계산이다** — 다행히 합계가 이미 출처에 있다.

스키마는 `estimated` 를 계속 허용하므로(다른 지표에는 쓸 수 있다) 이 결정은
**콘텐츠 검사로 고정했다**:

```
tests/schema.test.ts  describe('콘텐츠 정책 — 소요시간에 계산값을 쓰지 않는다')
  → 모든 장소의 metrics_origin.duration_min.kind 는 sourced 이거나 manual
```

## 규칙 14 — 출처가 주지 않은 값은 비운다

`distance_km` 을 nullable 로 바꿨다. 숲나들e 는 추천코스와 소요시간을 주면서
**거리는 100건 전부 주지 않는다.** 거리를 필수로 두면 그 자료를 한 건도 쓸 수 없고,
다른 데서 끌어오려면 이름 조인을 해야 하는데 그 경로는 동명이산 오염이 확인되었다.

**값과 출처는 짝이다.** 한쪽만 있으면 스키마가 거부한다 — 값만 있으면 어디서 왔는지
알 수 없고, 출처만 있으면 무엇의 출처인지 알 수 없다.

화면에는 `—` 와 `metric.unknown`("출처에 없는 값")이 뜬다. `metric.unverified`("검증되지 않음")와
**다른 뜻이다** — 하나는 값이 없는 것이고 하나는 값은 있는데 확인되지 않은 것이다.

`walk_min` 도 같은 이유로 nullable 이다. 출처는 역과 버스 번호를 주지만 **도보 분은 주지 않는다.**
0분은 "역 바로 앞"이라는 뜻이라 "모른다"와 다르다.

> ⚠️ 목록·지역·반나절 페이지도 함께 고쳐야 한다. 안 고치면 카드에 `null km` 이 찍힌다.

**출처가 산문으로만 주는 것은 산문으로 싣는다.** 교통정보를 억지로 `walk_min` 숫자에
욱여넣는 대신 `note_i18n` 에 그대로 담았다. 구조화할 수 없는 사실을 구조화하려다
없는 숫자를 지어내는 것이 규칙 13·14 가 막으려는 바로 그 실패다.

## 4-5. 미결 쟁점 — 이제 결정할 수 있다

**provenance 단위** — `docs/superpowers/specs/2026-08-13-provenance-granularity.md`

2-5 가 A/B/C 선택지를 결정할 실데이터다. 새 3건은 **표고는 두 기관이 확인했고
소요시간은 한 곳뿐**인데, 스키마는 장소 단위 상태 하나만 갖는다. 지금은 약한 쪽에 맞춰
`single_source` + `note` 로 두었지만, 그 결과 **교차 확인된 사실이 화면에 드러나지 않는다.**

`reconcile()` 은 여전히 호출부가 없다. `conflict` 는 손으로 넣었다. 넣을 재료가
`data/extracted/elevation-crosscheck.json` 에 생겼으므로 배선하거나 함수를 지워야 한다.

**`verified` 를 쓰는 장소가 이제 0건이다.** `bukhansan-dulle-1` 이 유일하게 `verified` 였는데,
네 지표가 전부 `manual` 이라 지표는 "검증되지 않음"을 세 번 말하면서 출처 블록은
"2건 이상으로 교차 확인"을 말하는 **같은 페이지 안의 모순**이었다. 나열된 두 출처에는
URL 도 조회 기록도 없는 Phase 1 초기 시드값이다. `single_source` 로 내리고 이유를 `note` 에 적었다.

> 교훈: **장소 단위 상태는 가장 약한 지표에 맞춘다.** 지표가 말하는 것과 출처 블록이
> 말하는 것이 어긋나면 독자는 어느 쪽도 믿지 않는다.

**영어 페이지에 한국어 데이터셋명이 그대로 뜬다.** `ProvenanceBlock` 이 `dataset` 원문을
출력하므로 영어 페이지에도 "산림청 국립자연휴양림관리소 숲나들e …"가 보인다. 8개 언어로 가면 커진다.

## 5-5. 함정

## 5-6. 검증 규율

**보고서를 믿지 않는다.**

1. 빌드 종료 코드가 아니라 **산출된 HTML 을 읽는다** — `dist/**/index.html` 의 `<dl class="metrics">` 를 직접 파싱한다
2. **통과한 것만 인용하는 보고서를 경계한다**
3. **한국어 페이지에서 라틴 산문을 grep 한다** — 이 검사로 찾은 `half-day-from-seoul` 미번역 문자열을 고쳐 **처음으로 0건**이 되었다
4. **가드가 실제로 발동하는지 임시 편집으로 확인하고 되돌린다** — `forest100.mjs` 의 `EXPECTED` 로 수행함(종료코드 1 확인)
5. **단위 테스트가 초록이어도 이음매는 별도 검증한다**
6. **키를 커밋하기 전 스테이징에서 실제 키 문자열을 grep 한다.** 매 커밋 전 수행 중
7. **되돌린 뒤에도 산출물을 다시 읽는다** — `b0d983f` 후 `dist` 에 `naismith`·`srtm` 흔적 0건 확인
8. **사용자가 하는 행동을 흉내낸다 — 링크는 눌러본다.** 페이지가 200 이고 요소가 보이는 것만
   검사하면 모든 카드가 404 인 사이트도 전부 초록으로 통과한다(2-14). 실제로 이동해 도착지를 확인한다.
9. **검색 요약을 근거로 삼지 않는다.** 검색이 "북한산 8코스 34.5km 17시간"을 내놓았으나
   기관 페이지에서 확인되지 않아 버렸다. 기관이 직접 공개한 페이지·파일만 인용한다
