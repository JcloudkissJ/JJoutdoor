## 2-5. 가드가 실제로 잡은 것 — 아차산 `coords` 는 정상이 아니다

처음 설계는 "장소의 `coords` = 정상, 산림청 시종점 중 최저 = 들머리"였다. 실행하자 멈췄다:

```
achasan: coords 가 정상이 아닌 것 같다 — DEM 118m, 공식 295m (차이 -177m)
```

`achasan.coords` (37.5556, 127.1017) 는 산허리를 가리킨다. **좌표를 손으로 고치면 출처 없는 값이 되므로**
설계를 바꿨다 — 정상도 들머리도 **등산로 폴리라인 꼭짓점**에서 뽑는다. 편집자의 손이 들어가지 않는다.

> ⚠️ **`achasan.coords` 는 아직 그대로다.** 순 상승 계산은 더 이상 이 값을 쓰지 않지만,
> 지도 표시용 좌표로서는 여전히 부정확하다. 출처 있는 좌표를 구할 때 함께 고친다.

## 2-6. 투영 변환 — 라이브러리 없이 구현했다

산림청 Esri JSON 의 `spatialReference.wkt` 가 매개변수를 전부 준다:

```
PCS_ITRF2000_TM / GRS80 / Transverse Mercator
FE 200000 · FN 600000 · 중앙자오선 127°E · 원점위도 38°N · 축척계수 1.0   (= EPSG:5186)
```

proj4 를 넣지 않고 Snyder 역변환을 그대로 옮겼다(약 40줄). **매 실행 앞에서 자체 점검한다** —
원점 `(200000, 600000)` 이 정확히 `38.000000, 127.000000` 으로 돌아오는지, 그리고 아차산 관리사무소의
실제 좌표가 아차산 위에 떨어지는지. 여기가 틀리면 엉뚱한 곳의 표고를 읽어오고,
**결과가 그럴듯해 보여 눈으로 잡을 수 없다.**

## 2-7. DEM 편향을 다루는 법

SRTM30m 은 공식 표고보다 평균 24m 낮다(30m 격자가 뾰족한 정상을 깎는다. 실측 6건, 범위 −8~−38m).

- **정상 표고로는 쓰지 않는다** — 100대명산 API 의 공식값이 더 정확하다
- **차이 계산에는 쓴다** — 최고점과 최저점을 **같은 DEM 으로** 찍으면 편향이 상쇄된다
- 그래서 최고점에 공식 표고를 대신 넣지 **않는다.** 넣으면 편향이 그대로 순 상승에 남는다

공개 인스턴스 제한: 요청당 100지점, 초당 1회, 하루 1,000회. 꼭짓점을 SRTM 격자(1/3600°)로 접어
아차산 2,572점 → 658칸, 인왕산 6,745점 → 720칸으로 줄였다.

# 3부 · 설계 원칙과 불변 규칙

## 유지되는 규칙 1~12

1. **언어 목록은 `src/config/languages.ts` 한 곳에만.**
2. **구조화 필드는 언어 독립.** `duration_min: 90` 이지 `"약 1시간 30분"` 이 아니다.
3. **`null` 은 "미확인"이며 절대 긍정 필터를 만족시키지 않는다.**
4. **조용한 실패보다 시끄러운 빌드 실패.**
5. **검증하지 않은 것을 검증했다고 표시하지 않는다.**
6. **번역 2등급.** 안전 정보는 사람 검수 의무.
7. **폰트는 언어별 스크립트만 로딩.**
8. **Swiss Modernism, 라이트 모드 고정.**
9. **URL 은 `/{lang}/{type}/{slug}`.**
10. **수치마다 출처를 데이터와 화면에 남긴다.** `estimated` 에 `method` 없으면 거부, `sourced` 에 `org` 없으면 거부.
11. **근거 없는 보정 계수를 넣지 않는다.** 여유는 조작된 상수가 아니라 안내 문구로 전달한다.
12. **타인의 데이터를 출처로 삼지 않는다.**

## 규칙 13 (신규) — 순 상승은 누적고도가 아니며, 그 결과는 최소치다

**이름**: 오르내림의 합이 아니므로 "누적고도"라 부르면 거짓이다. **"순 상승"**이면 계산한 그대로다.
method 도 나눈다 — 계산식은 `naismith_v1` 과 같지만 **입력의 출처가 다르므로**
`naismith_net_ascent_srtm30m_v1` 이다. 같은 이름을 쓰면 나중에 두 값을 구분할 수 없다.

**두 지점을 사람이 고르지 않는다**: 등산로 폴리라인의 모든 꼭짓점 중 최고/최저.
① 재현된다 ② **최저점 기준이라 순 상승이 가장 크게 나오고, 이는 "시간이 짧게 나오는" 위험한 방향의 반대쪽이다.**

**순환로에는 쓰지 않는다**: 둘레길처럼 오르내림을 반복하는 코스에서 순 상승은 실제 누적고도와 너무
멀어져 추정이라 부르기 어렵다. `bukhansan-dulle-1` 은 `ascent_m: null` + `metrics_origin.ascent_m: null` 로 두고
`duration_min` 은 `manual` 을 유지했다.

**결과가 실제보다 짧게 나온다는 것을 화면이 말한다**: 순 상승 누락 + 휴식·하산 누락이 겹친다.
규칙 11 에 따라 보정 계수를 곱하는 대신 문구로 전달한다. `duration_min.kind === 'estimated'` 인 장소에
`duration.minimum` 안내가 뜬다.

> "표시된 시간은 최소치다. 거리와 상승만으로 계산한 값이라 실제 오르내림·휴식·하산 시간이 빠져 있다.
> 반드시 여유를 두고 계획할 것."

**추정의 입력이 데이터에 남는다**: `metrics.ascent_m` + `metrics_origin.ascent_m`.
스키마가 강제하는 것 —

- 값과 출처는 **함께 있거나 함께 없다**(한쪽만 있으면 거부)
- **추정한 소요시간에 `ascent_m` 이 없으면 거부** — 입력 없이는 재현할 수 없다

이번 KNPS 콘텐츠가 문제를 더 선명하게 만들었다. 백운대코스는 거리·시간·난이도가 국립공원공단 한 곳,
표고·좌표가 100대명산 API 한 곳에서 왔다. **같은 수치를 두 출처가 확인한 것이 아니므로** `verified` 로
올리지 않고 `single_source` + `note` 로 두었다. 장소 단위 상태 하나로는 이 상황을 정확히 표현할 수 없다.

**`reconcile()` 은 여전히 호출부가 없다.** `provenance.verified`("Cross-checked against two or more official
sources") 문자열이 한 번도 쓰이지 않으면 죽은 코드다. 표현을 낮추거나 두 번째 출처를 실제로 확보해야 한다.

**영어 페이지에 한국어 데이터셋명이 그대로 뜬다.** `ProvenanceBlock` 이 `dataset` 원문을 출력하므로
영어 페이지에도 "국립공원공단 북한산 탐방로 — 백운대코스"가 보인다. 기존 동작이며 이번에 새로 생긴 것은
아니지만(아차산의 "서울시 등산로 정보"도 같다), 8개 언어로 가면 문제가 커진다.

## 5-6. 검증 규율

**보고서를 믿지 않는다.**

1. 빌드 종료 코드가 아니라 **산출된 HTML 을 읽는다** — 이번에도 `dist/**/index.html` 의 `<dl class="metrics">` 를 직접 파싱해 확인했다

6. **키를 커밋하기 전 스테이징에서 실제 키 문자열을 grep 한다.** 매 커밋 전 수행 중
